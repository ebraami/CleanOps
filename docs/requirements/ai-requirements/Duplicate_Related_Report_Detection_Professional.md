Duplicate / Related Report Detection Requirements

**Work Package: AI Requirements
**Status: Updated per Team Lead Feedback
Data Model: REPORTS

# Objective

Define a duplicate and related-report detection mechanism using classification embeddings generated by the AI classification pipeline, PostGIS spatial filtering, temporal filtering, and embedding similarity comparison. Potential matches are surfaced as recommendations only and never automatically merged.

# Architecture Alignment

Duplicate detection reuses the classification embedding already produced by the AI/Classification pipeline. No separate duplicate-detection embedding is generated, ensuring consistency with the CleanOps architecture and avoiding redundant storage and processing.

# Detection Pipeline

1\. Reuse existing classification embedding. 2. Spatial pre-filter on REPORTS. 3. Temporal pre-filter on REPORTS. 4. Candidate set creation. 5. Cosine similarity comparison. 6. Present ranked recommendations.

# Spatial Pre-Filter (REPORTS)

SQL Example:
SELECT \* FROM reports WHERE ST\_DWithin(location, :incoming\_location, 500);

# Temporal Pre-Filter (REPORTS)

SQL Example:
SELECT \* FROM reports WHERE created\_at >= :incoming\_time - INTERVAL '24 HOURS';

# Combined Candidate Query

SELECT \* FROM reports WHERE ST\_DWithin(location,:incoming\_location,500) AND created\_at >= :incoming\_time - INTERVAL '24 HOURS';

# Similarity Thresholds

\>= 0.90 Strong Duplicate
0.80-0.89 Probable Duplicate
0.70-0.79 Related Report
< 0.70 No Match

# Manual Review Requirement

The system suggests matches and displays similarity scores. Reports are never automatically merged, closed, or deleted.

# Inputs

Title, Description, Latitude, Longitude, Created At, Classification Embedding.

# Outputs

Candidate Report ID, Similarity Score, Match Type, Rank, Recommendation List.

# Precision Target

Minimum precision target: 70% confirmed duplicates.

# Testing Strategy

Validate against historical reports containing confirmed duplicates, related reports, and non-duplicates. Measure Precision, Recall, and False Positive Rate.

# Final Solution Summary

The solution reuses classification embeddings already generated by the AI classification pipeline. Candidate reports are retrieved from the REPORTS data model using spatial and temporal filters, then compared through cosine similarity. Results are surfaced as recommendations only, with no automatic merge actions.
